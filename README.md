# AI 海报自动化工作台 · 第三阶段

纯 HTML + CSS + JavaScript 的海报制作工作台。左侧填客户需求、上传素材，右侧实时排版；支持拖动缩放、AI 背景回传和原尺寸 PNG/JPG 导出。可通过 GitHub Pages 访问，不需要 Python 后端、账号、密钥或付费 API。

## 制作一张海报

1. **填写需求**：设置宽高像素、主题、主副标题、正文、行动引导，选择行业、风格和色系；也可先点“填入示例”。
2. **选择商业版式**：保留原来的四种布局，新增左文右图、上文下图、中心视觉、产品主视觉、活动促销、电商商品、简约品牌、国风宣传，共 12 种。“重新排版”循环切换全部模板。
3. **上传客户素材**：在“客户素材”选择产品图、人物图、Logo、二维码或其他参考素材，再选图片。支持多张上传，图片会直接出现在画布上。
4. **调整素材**：点击画布中的图片选中，拖动移动，拖右下角圆点等比缩放。也可从素材列表选择，用大小滑块、水平及垂直位置调整。点“删除选中素材”删除；画布聚焦时也可按 Delete。参考图也会参与导出，不需要时请删除。
5. **应用模板**：重新排版或选择商业模板会重新安放产品、人物和参考图，Logo 与二维码保留当前位置；之后可继续微调。修改画布尺寸会保持图片原始比例，并约束在画布范围内。
6. **制作 AI 背景**：查看“AI 背景制作”的完整中文提示词，点“复制背景图提示词”，手动到豆包、即梦、可灵等工具生成背景，再点“上传 AI 背景图”。背景自动等比铺满并居中裁切；可移除恢复渐变几何背景。本站不会调用这些工具，它们的费用和隐私政策由相应平台决定。
7. **导出交付**：点“导出 PNG”或“导出 JPG”，按填写的实际像素保存，例如 1080×1920。PNG/JPG 与预览共用绘制器，包含背景、文字和素材，不含蓝色选择框及缩放手柄。JPG 为高质量不透明图片。也保留背景提示词复制、完整方案复制和 Markdown 下载。
8. **交付前检查**：核对全部文案、价格、日期、宣传依据、字体与素材授权；在手机扫码核验二维码。空字段会显示待确认提示文字，正式导出前应填写真实内容。

## 数据和使用限制

- 客户文案、素材与背景图仅在当前浏览器内处理，没有上传、云存储或统计服务。刷新、关闭页面后会丢失编辑内容；请及时导出，源素材另行保管。
- 支持 PNG、JPG、WebP；不支持 SVG、GIF。每张不超过 15 MB，解码后不超过 2400 万像素；前景素材最多 20 张。不会自动抠图，透明产品或人物图建议使用透明 PNG。
- 导出图片单边最多 8192 像素、总面积最多 2400 万像素。超限会提示调整，不会偷偷降低分辨率。设备内存不足时也会明确报告导出失败。
- 可设置 100–20000 像素的画布预览；超出图片导出限制时，仍能查看预览及下载 Markdown 方案。
- 素材可自由覆盖文字，导出前请检查遮挡。长文自动缩小字号，仍放不下会显示提示。不同设备的系统字体可能不同；不会下载外部字体。
- 浏览器禁止自动复制时，页面提供可选中的文本框供手动复制。
- 导出的是 RGB 位图，不是可编辑设计源文件或印刷 CMYK 文件；印刷前向印厂确认物理尺寸、DPI 和出血。AI 背景不包含最终文字或二维码，它们应由工作台叠加。

## GitHub Pages 部署

网站全部运行文件在 `web/`，首页是 `index.html`。CSS 和 JS 使用相对路径，支持 `/codex-test/` 项目子目录。没有在线图片依赖、构建依赖或手动配置的 Secret。`app.py` 仅为可选本地预览工具，不会发布到网站。

首次启用：

1. 打开仓库 **Settings → Pages**。
2. **Build and deployment → Source** 选择 **GitHub Actions**。
3. 打开 **Actions → Deploy poster workbench to GitHub Pages**。如未自动运行，点 **Run workflow → main → Run workflow**；如果启用前运行失败，可点 **Re-run all jobs**。
4. 等待 `build`、`deploy` 变绿，回到 **Settings → Pages → Visit site**。

默认地址预计为 `https://marymartin2026.github.io/codex-test/`；上线状态以实际部署结果为准。以后推送到 `main` 会自动执行规则测试，再上传 `web/` 并部署。站点更新后如仍显示旧界面，请强制刷新。

工作流使用 GitHub 提供的临时部署权限，无需填写密钥。若仓库策略禁用了 Actions，先在 **Settings → Actions → General** 检查。Pages 能否启用取决于仓库可见性和账户政策。

## 可选本地预览

安装 Python 3 后，在项目目录运行：

```bash
python3 app.py
```

Windows 可使用 `python app.py`。在同一台电脑浏览器打开 `http://127.0.0.1:8000`，按 Ctrl+C 停止。端口占用可加 `--port 8001`。云平台需要所有接口时可加 `--host 0.0.0.0`，只用于可信环境，服务没有登录功能。

## 项目目录

```text

tests/browser-smoke.js      原有功能的浏览器回归检查
tests/editor-browser.js     素材操作与图片导出检查
```

## 测试

开发环境有 Node.js 18+ 时：

```bash
node --test tests/*.test.js
```

日常使用不需要 Node.js。浏览器检查需要开发环境已有 Playwright 和 Chromium；先启动静态服务器，再运行：

```bash
CHROMIUM_PATH=/usr/bin/chromium node tests/browser-smoke.js
CHROMIUM_PATH=/usr/bin/chromium node tests/editor-browser.js
```

可用 `BASE_URL` 指定带项目子目录的测试地址。浏览器检查覆盖实时预览、12 种模板、提示词与 Markdown、五类素材、拖动、两种缩放、删除、背景回传、PNG/JPG 实际尺寸与导出像素、超限提示、无效图片、移动布局和无上传网络请求。GitHub Actions 默认运行无需第三方包的单元检查。
