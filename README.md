# AI 海报自动化工作流 · 第二阶段工作台

面向客户海报制作的纯静态网页工作台。左侧填写尺寸、主题、文案、行业、风格和色系，右侧实时显示等比例海报草稿，并同步生成六部分制作方案。

**当前使用内置规则，不调用 AI 模型、不接入收费 API。预览背景由渐变、色块和几何元素组成，不生成 AI 图片，也不导出成品海报图片。** 背景提示词可手动粘贴到你选择的图片工具；第三方工具的收费及隐私规则由该工具决定。

## 部署到 GitHub Pages（推荐，无需自己运行 Python）

网站的全部运行文件都在 `web/`：`index.html`、`styles.css`、`planner.js`、`app.js`。没有后端、构建步骤、付费 API、第三方运行依赖或需要手动配置的密钥。`app.py` 只保留作为可选本地预览工具，不会上传到 Pages 站点。

首次启用步骤：

1. 确保本项目文件及 `.github/workflows/pages.yml` 已提交到仓库的 `main` 分支。
2. 打开 GitHub 仓库 **Settings（设置）→ Pages**。
3. 在 **Build and deployment → Source（来源）** 选择 **GitHub Actions**（如页面显示保存按钮则保存）。
4. 打开仓库 **Actions**，选择 **Deploy poster workbench to GitHub Pages**。若已有失败记录，启用 Pages 后可点 **Re-run all jobs**；也可以点 **Run workflow → main → Run workflow** 重新部署。
5. 等待 `build` 和 `deploy` 均显示绿色。点击部署记录里的 **github-pages** 网站链接，或回到 **Settings → Pages → Visit site**。

此仓库默认网站地址预计为：`https://marymartin2026.github.io/codex-test/`。**地址是否已可访问，以部署成功后的链接为准，添加配置文件本身不代表已经上线。** 以后推送到 `main` 会自动测试并重新部署。

工作流只上传 `web/`，因此部署产物根目录的首页是 `index.html`。CSS 和 JS 使用相对路径，可在 `/codex-test/` 等项目子目录下正常加载。背景来自 CSS，未依赖外部图片或字体服务。

工作流使用 GitHub 自动提供的临时部署权限，不需要创建或填写任何 Secret。若 Actions 被禁用，在 **Settings → Actions → General** 中按仓库策略启用允许的官方 Actions。若 Pages 设置要求升级套餐，先确认仓库可见性和账户支持情况；本项目不依赖付费服务，无需为此填写付款信息。

## 可选：本地预览


需要 Python 3，不需要安装任何第三方包。打开项目目录的终端，输入：

```bash
python3 app.py
```

Windows 如没有 `python3` 命令，可使用 `python app.py`。

看到启动提示后，在同一台电脑的浏览器打开 `http://127.0.0.1:8000`。云环境中可使用平台提供的端口访问功能（如果可用）；云端地址不能直接当作自己电脑上的地址使用。

端口被占用时：`python3 app.py --port 8001`。停止：终端按 `Ctrl+C`。

默认仅本机访问。如云平台要求监听所有接口，可使用 `python3 app.py --host 0.0.0.0`；只应在可信环境使用，服务没有登录功能。

## 使用步骤

1. 点“填入示例”可立即看到完整效果，也可从空表单开始。
2. 填写像素尺寸与主题；右侧画布会按宽高比例缩放，桌面左右显示，手机上下显示。
3. 输入主标题、副标题、正文与行动引导，预览自动更新。留空时显示提示文字，不算客户确认的内容。
4. 选择行业、风格和色系，观察背景、文字颜色、字体大小及默认版式的变化。
5. 点“重新排版”，依次切换左对齐留白、居中聚焦、底部叙事、分栏构图。切换风格会使用该风格的默认版式。
6. 点“复制背景图提示词”，复制与当前版式同步的背景说明，可粘贴到自己选择的图片工具。
7. 点“导出方案（Markdown）”，下载最新需求对应的完整 `.md` 文档。下方可展开、复制六部分制作方案。
8. 人工核对价格、日期、联系方式、宣传依据及素材授权，再交客户确认。

所有预览、提示词与方案在输入时自动更新，不需要每次点击生成。输入仅在当前页面内处理，不发送到服务器或第三方；刷新会清空内容，没有云存储或历史记录。下载文件由你自行保管。

浏览器不允许自动复制时，页面会显示可选中的文本框，按 Ctrl+C（Mac 按 ⌘C）或在手机长按复制即可。尺寸需为 100–20000 的整数像素；无效尺寸或空主题下，复制与导出按钮会暂停使用，防止导出旧方案。

长文案会尝试自动缩小字号，仍放不下时会提示调整文案、尺寸或版式。不会删改导出方案中的客户原文。非常狭长的画布虽然保持比例，但文字可能难以阅读，建议改用适合投放渠道的尺寸。

## 验证方法

如安装了 Node.js 18 或更高版本，运行：

```bash
node --test tests/planner.test.js
```

Node.js 仅供检查，日常使用不需要。也可在网页填入示例，观察预览、切换版式，检查复制及下载。

开发者如已有 Playwright 和 Chromium，在服务启动后可运行浏览器检查：

```bash
# Linux 示例；按实际浏览器路径调整
CHROMIUM_PATH=/usr/bin/chromium node tests/browser-smoke.js
# 也支持 BASE_URL 指定带子目录的测试地址
```

此可选检查依赖开发环境已有的 Playwright，不属于日常运行依赖。检查覆盖实时文字、横竖方形比例、四种版式、风格字号、配色、复制与回退、Markdown 导出、长文提示、非法输入和手机布局。

## 当前版本的边界

规则建议是制作起点，不会自动理解每条自由文字约束，也不能自动判断广告合规、字体授权或商业效果。未提供的内容标为待确认，不编造客户事实。印刷前需向印厂确认物理尺寸、分辨率、出血和色彩模式。

预览使用系统现有字体，宋体或黑体的具体显示取决于设备，不会自动下载字体。后续可逐步增加客户方案保存、成品图片导出，或人工确认后再接 AI 文案及背景图生成。当前不需要 API Key；代码通过 GitHub Actions 发布静态网站，不自动向客户发布海报。
